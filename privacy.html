Privacy policy

Reck Profile Backup is a personal-use application operated by its owner on the owner's Windows computer. This policy describes the application's backup operation and Google Drive access. It is not a hosted backup service for the general public.

Data the application accesses

  • Selected local source files and their names, sizes, timestamps and hashes.
  • Google authorization tokens needed to connect to the Drive account that the user approves.
  • Google Drive file and folder metadata, including names, identifiers and sizes, and the account's storage-quota information. The metadata permission can cover files outside the dedicated backup folder.
  • Contents of Google Drive files created by the app or otherwise authorized through its drive.file permission, including the uploaded archive and public recovery-tool files used for verification.

The app requests drive.file and drive.metadata.readonly. It does not request access to Gmail messages, Google Calendar or Google Contacts. It does not receive the user's Google account password.

How the data is used

The app uses this data to create backups, upload and verify them, check available storage, recover interrupted publications, identify its owned files and enforce the selected backup retention. Cloud verification streams the downloaded encrypted backup through SHA-256 checking without saving a second full downloaded copy.

The app does not sell Google user data, use it for advertising, or send it to an AI service for model training. Its use of information received from Google APIs is limited to the backup functions described here.

Where data is stored and shared

Selected source files are copied into an unencrypted local working folder. Compressed archives use WinZip AE-2 AES-256 encryption, but archive filenames and cloud ownership/verification metadata are not encrypted. Local logs and manifests also contain file paths and operational metadata.

The user can enable Google Drive and Microsoft OneDrive cloud destinations and connected USB copies. The same selected local source data can be included in archives sent to each enabled destination. Google Drive authorization tokens are not shared with Microsoft or placed inside the backup archives.

Transfers use rclone running locally. Its saved OAuth configuration is encrypted with a random configuration key; that key and the unattended archive password are protected with Windows current-user DPAPI. The Google OAuth client secret is also DPAPI-protected. This does not protect against every threat to a compromised Windows account or computer.

Storage providers process the data stored with them under their own policies. The app owner does not operate a separate server that receives backup data from this application.

Retention and deletion

The app keeps its current local and USB archive set and the configured one to four completed weekly sets in each enabled cloud. A replacement is verified before excess older owned cloud sets are permanently removed. A journaled incomplete upload can be removed and retried only under the application's ownership and content checks. An empty journaled folder is removed using an empty-only operation.

Ordinary files deleted from the source computer remain in the saved working set until the user removes or excludes them. Revoking account access or disabling a destination does not automatically delete backups already stored there. The user can delete those backups and local program data when no longer needed, while retaining any copies they wish to keep.

User controls

The owner chooses source exclusions, destinations, schedule and cloud retention. Google access can be revoked through Google Account controls for connected applications. After revocation, future Google operations require reconnection; existing cloud backup files remain until deleted.

This documentation website

The static website has no login, upload forms, advertising, analytics scripts or cookies added by the app owner. When hosted through GitHub Pages, GitHub logs visitors' IP addresses for security purposes under its own policies. See GitHub Pages documentation.

Contact and updates

Contact the app owner through the support email configured on the Google OAuth consent screen. This policy will be updated when the application's data practices change. The effective update date appears at the top of this page.
